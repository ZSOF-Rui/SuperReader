网页实验 · Web NFC

浏览器能读 NDEF 标签，
读不了交通卡和银行卡。

这是卡阅的独立网页实验：在支持 Web NFC 的 Android Chrome 里，靠近 NDEF 标签就能看到文本、网址或 MIME 记录。它不写标签，也不上传数据。

结论先说：完整的交通卡 / 银行卡 / 护照网页版不可行。Web NFC 只提供 NDEF 消息，不暴露 ISO 7816 APDU，也不支持 FeliCa 或 MIFARE Classic；这些芯片数据必须由原生应用读取。

  1. 用 Android 手机的 Chrome 打开本页；桌面浏览器没有手机 NFC。
  2. 系统 NFC 已开启，手机保持解锁并停留在本页。
  3. 页面通过 HTTPS 或 localhost 打开；file:// 不行。
  4. 手边有一张已经写好内容的 NDEF 标签（文字、网址或 MIME）。

本页只读 NDEF，不会碰交通卡、银行卡或护照芯片；也不会写标签。读卡位置因手机型号而异。

能力边界

能读什么，读不到什么

Web NFC 的定位很明确：它是标签消息 API，不是智能卡 APDU 通道。把这两类东西混在一起，就容易得出“网页版什么都能读”的错误结论。

NDEF 标签

NDEF 是 NFC Forum 定义的标签消息格式，常见于网址标签、产品标签、海报与门禁贴。

  • 文本、URL、MIME 记录
  • Smart Poster 的子记录
  • 标签序列号（设备提供时）

本页可以读取并展示这些记录。

交通卡 / 银行卡 / 护照

这些不是 NDEF 标签，而是需要 APDU 或专用命令的智能卡芯片。

  • ISO 7816 / ISO-DEP APDU：银行卡、交通联合、护照
  • FeliCa：八达通、Suica
  • MIFARE Classic：悠游卡

Web NFC 不暴露这些命令，本页读不到，也不会假装能读。

可行性结论

为什么不做完整网页版

不是页面写不出来，而是浏览器根本没有提供读取这些芯片所需的接口。

  1. API 只到 NDEF。Web NFC 的 NDEFReader 读取的是标签消息层，不提供 ISO 7816 APDU 通道，也不能选择支付应用或证件应用。银行卡、交通卡与护照都依赖 APDU 会话，网页拿不到。
  2. 专用技术同样缺席。八达通、Suica 走 FeliCa，悠游卡走 MIFARE Classic；这两套命令都不在 Web NFC 的暴露范围内，不能用 NDEF 接口替代。
  3. 浏览器支持很窄。主要实现是 Chrome for Android；iOS Safari 没有 Web NFC，桌面 Chrome 通常没有 NFC 硬件。页面还必须处于安全上下文：HTTPS 或 localhost。
  4. 前台限制。Web NFC 扫描要求页面在前台；切到后台、锁屏或离开页面后就不能继续监听。这不是适合长时间读卡的运行环境。
  5. 替代方案不是独立网页版。Android 开发版的局域网桥接可以让电脑借用手机 NFC，但需要安装 App；电脑只接收脱敏文本，不能发送 APDU，也不是“打开网页就能读卡”。

所以：网页适合做 NDEF 小工具和边界说明；完整的交通卡、银行卡与电子证件读取，仍由 Android 原生正式版承担。

完整读卡

交通卡、银行卡、电子证件，还是用 Android 正式版。

正式版只读，读卡与解析在本机完成；INTERNET 权限仅用于启动后与手动检查更新。当前公开版本为 1.8.0，本站下载区提供 APK 与 SHA-256 校验值。
